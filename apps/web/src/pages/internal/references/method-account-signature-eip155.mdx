# Method: `account-signature.eip155.v1`

This method proves that the current ENS authority and the EVM account stored in
one live ENS address record both approved the same common claim.

> **Status:** The procedure below is the proposed v0 profile. The identifier
> remains experimental until target-chain finality rules and conformance vectors
> are frozen.

## Applicability

| Property          | Requirement                   |
| ----------------- | ----------------------------- |
| `recordType`      | `addr`                        |
| Record value      | Exactly 20 bytes              |
| Descriptor method | `account-signature.eip155.v1` |
| Descriptor `u`    | Required HTTPS URI            |
| Result type       | `control`                     |
| Maximum lifetime  | 7,776,000 seconds             |

The method supports these coin-type mappings:

| Coin type                         | Target EIP-155 chain ID |
| --------------------------------- | ----------------------- |
| `60`                              | `1`                     |
| `0x80000001` through `0xffffffff` | `coinType & 0x7fffffff` |

`0x80000000` is excluded because it maps to chain ID zero rather than one
concrete target chain. Other legacy SLIP-44 EVM coin types are unsupported.

## Target Derivation

Interpret the exact 20 resolver bytes as the EVM account address. Derive its
EIP-55 checksummed hexadecimal form and set:

```text
target = "eip155:" + decimal(chainId) + ":" + checksummedAddress
```

For example:

```text
eip155:1:0x22227A31dd842196A246d8f3b775998560eAa61d
```

The CAIP-10 chain ID is canonical unsigned decimal. The address MUST have the
EIP-55 casing derived from the 20 live bytes. A proof-supplied target is not
used to select the chain or account.

`valueHash` remains Keccak-256 of the exact 20 resolver bytes, not of the
CAIP-10 string.

## Proof URI

`u` MUST be an absolute `https:` URI with no username, password, or fragment.
It points directly to one proof envelope. This method does not use a proof key.

The verifier MUST retrieve the exact URI with the request, TLS, credential,
redirect, status, media-type, streaming body, deadline, and server network
controls defined by
[`https-origin.v1`](./method-https-origin#request-policy) and its
[network policy](./method-https-origin#network-policy).

The proof host is only a transport. It is not the target account and does not
contribute target evidence. No alternate URI, IPFS gateway, content search, or
scheme fallback is permitted by this profile.

## Proof Schema

The common envelope's `proof` object is exactly:

```json
{
  "proof": {
    "targetSignature": "0x..."
  }
}
```

`targetSignature` is required exactly once and is a lowercase hexadecimal byte
string. No other proof member is permitted.

The target account signs the same `commonClaimDigest` validated for the
authority:

```text
targetSignature = targetAccount.signTypedData(commonClaim)
```

The complete common claim, domain, types, and field order are those defined by
[Claims, Envelopes, and Signatures](./claims-envelopes-and-signatures).

## Target-Chain Snapshot

Before validating `targetSignature`, select one block on the derived EIP-155
chain and record its number, hash, and timestamp. The runtime MUST identify the
chain by the derived chain ID; the proof MUST NOT supply an RPC endpoint or
chain override.

Target code lookup and every ERC-1271 call MUST use that one block. If its hash
is removed by a reorganization before the result is returned, discard and
repeat the attempt.

## Target Signature

Read target-account code at the target-chain block.

### EOA target

When code is empty:

- `targetSignature` MUST be exactly 65 bytes encoded as `r || s || v`;
- `v` MUST be `27` or `28`;
- `r` and `s` MUST satisfy the EOA bounds defined by
  [Claims, Envelopes, and Signatures](./claims-envelopes-and-signatures#eoa-authority);
  and
- recovery over `commonClaimDigest` MUST equal the 20-byte live address.

Compact EIP-2098 signatures, `v` values `0` or `1`, and personal-sign
prefixes are not accepted.

### Contract target

When code is nonempty:

1. require a nonempty target signature of at most 8,192 bytes;
2. `staticcall`
   `isValidSignature(commonClaimDigest, targetSignature)` at the target-chain
   block;
3. require call success; and
4. require exactly one canonical ABI-encoded `bytes4` equal to
   `0x1626ba7e`.

Raw four-byte output, malformed ABI, wrong padding, trailing data, reverts, and
every other result are invalid. Contract validation MUST NOT fall back to EOA
recovery. Undeployed counterfactual accounts are unsupported.

## Method Verification

In addition to every common check, require:

1. the live record, coin type, address length, descriptor, and proof URI satisfy
   this profile;
2. chain ID and CAIP-10 target are derived from the live selector and bytes;
3. the exact proof URI returns one bounded closed envelope;
4. every common claim field matches, including the exact method and target;
5. the ENS authority signature is valid at the ENS snapshot;
6. the target signature is valid at the target-chain snapshot;
7. both snapshots remain acceptable under runtime policy; and
8. all lifecycle bounds pass immediately before returning.

The two required signatures MAY be byte-identical when the ENS authority and
target EOA are the same account. Each is still validated against its own
live-derived account role.

## Freshness

`methodEvidenceValidUntil` is absent unless the target contract exposes a
profile-defined hard expiry, which v1 does not currently define.

`methodEvidenceCacheUntil` MUST be no later than the target-chain snapshot's
maximum permitted reuse time. The common five-minute ceiling still applies.
The 90-day claim lifetime never permits a 90-day cached account-state result.

## Unfrozen v0 Parameters

Stable `account-signature.eip155.v1` conformance still requires:

- target-chain finality and maximum snapshot-age rules;
- chain availability and RPC trust requirements;
- EIP-55, coin-type, CAIP-10, EOA, and ERC-1271 vectors;
- target contract revocation and cache semantics;
- final confirmation of the 90-day maximum lifetime; and
- proof-URI HTTP deadline and content-coding values.
