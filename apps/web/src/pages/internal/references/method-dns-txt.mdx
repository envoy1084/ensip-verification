# Method: `dns-txt.v1`

This method proves publication of the common envelope in
DNSSEC-authenticated DNS beneath the exact hostname derived from one ENS text
record.

## Applicability

| Property          | Requirement                     |
| ----------------- | ------------------------------- |
| `recordType`      | `text`                          |
| Record value      | Eligible HTTPS URL              |
| URL host          | Domain name; IP hosts forbidden |
| Descriptor method | `dns-txt.v1`                    |
| Descriptor `u`    | Forbidden                       |
| Result type       | `control`                       |
| Maximum lifetime  | 31,536,000 seconds              |

Parse the record with the URL-acceptance rules from
[`https-origin.v1`](./method-https-origin). Require the parsed host to be a
domain, not IPv4 or IPv6.

Set `target` to the serialized URL hostname in lowercase ASCII A-label form.
Do not include a trailing dot, scheme, port, path, query, or fragment.

## Proof Owner

Calculate the common 32-byte `proofKey`. Encode it using RFC 4648 base32 with:

- lowercase alphabet `a-z2-7`;
- no padding; and
- exactly 52 output characters.

Construct the absolute DNS owner:

```text
<proof-key-base32>._ens-record-verification.<target>.
```

Construct and validate the complete DNS wire name before querying. Every label
MUST be at most 63 octets and the complete wire name, including length octets
and root terminator, MUST be at most 255 octets.

Query exactly QCLASS `IN`, QTYPE `TXT`. Parent fallback, wildcard search,
alternate prefixes, and descriptor proof URIs are forbidden.

## DNSSEC Validation

A positive result requires the final answer and every dependency to validate as
`Secure` under the current IANA root trust-anchor set.

`Insecure`, `Bogus`, and `Indeterminate` are non-positive. The verifier MUST
NOT retry without DNSSEC or dispatch another method.

Use the attempt's `checkedAt` as the DNSSEC validation time. Every required
RRSIG MUST satisfy its inception and expiration interval at that time.

Validation MAY be local or delegated to a trusted validating resolver over an
authenticated channel. The `AD` bit from an arbitrary recursive resolver is
not sufficient evidence. A delegated validator MUST provide enough
authenticated status and freshness metadata to enforce this method.

### Aliases

A completely Secure CNAME or DNAME chain MAY be followed for at most eight
alias steps. The verifier MUST reject:

- a loop;
- conflicting CNAME, DNAME, or terminal data;
- an alias or synthesized-name overflow;
- an insecure, bogus, or indeterminate link; or
- more than eight followed aliases.

DNAME processing MUST validate the signed DNAME RRset and its synthesized CNAME
according to RFC 6672.

The terminal owner reached after aliases is used only for retrieval. The signed
common `target` remains the hostname derived from the live ENS record.

## TXT Assembly

At the terminal owner, require exactly one TXT RDATA.

1. Concatenate that RDATA's character strings in wire order without separators.
2. Do not include zone-file quotes, escapes, presentation whitespace, or chunk
   boundaries.
3. Reject the value after it exceeds 2,048 concatenated bytes.
4. Decode the result as strict UTF-8 JSON without a byte-order mark.
5. Parse the common closed proof envelope.

Zero TXT RDATA means no proof. More than one TXT RDATA is ambiguous and invalid.
Separate RDATA MUST NOT be concatenated. A proof over 2,048 bytes MUST NOT fall
back to another transport.

## Proof Schema

The TXT value contains the common closed proof envelope with:

```json
{ "proof": {} }
```

`proof` MUST contain no members. The Secure TXT publication is the method's
target-controlled evidence.

## Method Verification

In addition to every common check, require:

1. the live record and descriptor satisfy the applicability rules;
2. the canonical hostname, proof key, and DNS owner are derived from live
   inputs;
3. the complete DNSSEC proof and alias chain are Secure;
4. exactly one bounded TXT RDATA is assembled and parsed;
5. every common claim field matches, including
   `claim.method == "dns-txt.v1"` and the derived hostname target;
6. the authority signature is valid;
7. `proof` is exactly empty; and
8. the common time and DNS freshness checks pass.

## Freshness

The DNSSEC validator MUST calculate `methodEvidenceCacheUntil` as no later
than the earliest remaining authenticated reuse bound across:

- the terminal TXT RRset;
- every CNAME or DNAME RRset used;
- every DNSKEY and DS RRset used by the validation chain; and
- every covering RRSIG expiration.

TTL age already spent in caches MUST be deducted. The result cache is also
capped by `checkedAt + 300` and every hard validity bound.

DNS freshness is a cache bound, not a claim hard expiry.
`methodEvidenceValidUntil` is absent.

## Runtime Boundary

A runtime without a DNSSEC validator or authenticated validating-resolver
service cannot conform to this method. Standard browser DNS APIs do not expose
the required chain, status, and freshness information.

## Unfrozen v0 Parameters

Stable `dns-txt.v1` conformance still requires:

- signed-zone positive, negative, alias, rollover, and expiry vectors;
- exact trusted-resolver interface requirements;
- target-host and internationalized-name vectors; and
- diagnostic and negative-cache behavior for DNS failures.
