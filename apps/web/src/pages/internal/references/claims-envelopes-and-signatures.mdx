# Claims, Envelopes, and Signatures

Every method uses the same common claim and authority-signature procedure. The
selected method defines only the closed `proof` object and its target evidence.

## Common Claim

The EIP-712 type is exactly:

```solidity
struct ENSRecordVerification {
  string name;
  bytes32 node;
  string recordType;
  string recordKey;
  bytes32 valueHash;
  uint32 authorityVersion;
  address authority;
  string method;
  string target;
  uint64 issuedAt;
  uint64 validUntil;
}
```

The encoded type string is:

```text
ENSRecordVerification(string name,bytes32 node,string recordType,string recordKey,bytes32 valueHash,uint32 authorityVersion,address authority,string method,string target,uint64 issuedAt,uint64 validUntil)
```

Field names, types, and order MUST NOT change under `ensrv1`.

| Field              | Required value                                       |
| ------------------ | ---------------------------------------------------- |
| `name`             | Exact normalized name used for live resolution       |
| `node`             | `namehash(name)`                                     |
| `recordType`       | Type derived from the caller's target selector       |
| `recordKey`        | Exact key derived from the target selector           |
| `valueHash`        | Keccak-256 of the decoded live resolver value bytes  |
| `authorityVersion` | Live descriptor field `a`                            |
| `authority`        | Account returned by the selected authority algorithm |
| `method`           | Live descriptor field `m`                            |
| `target`           | Canonical target derived by the selected method      |
| `issuedAt`         | Claim issuance time in Unix seconds                  |
| `validUntil`       | Exclusive claim expiry in Unix seconds               |

The verifier MUST derive and compare every field. A proof-supplied value is
never authoritative.

## EIP-712 Digest

For `ensrv1` on Ethereum mainnet, the domain is exactly:

```text
name: ENS Record Verification
version: 1
chainId: 1
```

The domain type contains `name`, `version`, and `chainId` in that order. It
does not contain `verifyingContract` or `salt`.

```text
domainType =
  EIP712Domain(string name,string version,uint256 chainId)

domainSeparator =
  hashStruct(domainType, {
    name: "ENS Record Verification",
    version: "1",
    chainId: 1
  })

commonClaimDigest =
  keccak256(0x1901 || domainSeparator || hashStruct(commonClaim))
```

EIP-712 dynamic strings are hashed from their exact UTF-8 bytes. The verifier
MUST NOT hash the proof-envelope JSON serialization.

## Proof Envelope

The decoded JSON value MUST have exactly these top-level members:

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
    "authorityVersion": "1",
    "authority": "0x1234567890abcdef1234567890abcdef12345678",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x...",
  "proof": {}
}
```

`v`, `claim`, `authoritySignature`, and `proof` are required exactly once.
`v` MUST equal `ensrv1`. `claim` and `proof` MUST be objects.

The `claim` object is closed and contains every common-claim field exactly
once. The selected method defines the exact closed shape of `proof`.

## JSON Parsing

The verifier MUST:

1. enforce the applicable decoded-byte limit before parsing;
2. decode strict UTF-8 without a byte-order mark;
3. require exactly one top-level JSON value and no trailing non-whitespace
   bytes;
4. require that value to be an object;
5. detect duplicate member names after JSON escape decoding and before
   constructing a normal map;
6. reject unknown, missing, or wrongly typed members at every closed-object
   level;
7. reject lone Unicode surrogates and other invalid scalar values; and
8. apply the canonical decimal and hexadecimal rules from
   [Data Types and Encoding](./data-types-and-encoding).

Member order, insignificant JSON whitespace, and equivalent JSON string escapes
do not affect the decoded claim. Parsed strings MUST NOT be normalized.

The decoded envelope limit is 256 KiB unless the method sets a lower limit.
Maximum nesting, member count, and individual-string limits remain unfrozen.
Implementations MUST impose finite documented limits and MUST detect duplicate
members without first losing them in a map.

## Claim Comparison

After parsing and before signature validation, require:

```text
claim.name             == normalizedName
claim.node             == namehash(normalizedName)
claim.recordType       == derivedRecordType
claim.recordKey        == derivedRecordKey
claim.valueHash        == keccak256(liveValueBytes)
claim.authorityVersion == descriptor.authorityVersion
claim.authority        == resolvedAuthority
claim.method           == descriptor.method
claim.target           == methodDerivedTarget
```

Time fields are validated by [Lifecycle and Results](./lifecycle-and-results).
Any mismatch is non-positive.

## Authority Signature

Read `eth_getCode(authority)` at the ENS evaluation block.

### EOA authority

When the returned code is empty:

- `authoritySignature` MUST be exactly 65 bytes encoded as `r || s || v`;
- `v` MUST be `27` or `28`;
- `r` MUST be in `[1, n - 1]`, where
  `n = 0xfffffffffffffffffffffffffffffffebaaedce6af48a03bbfd25e8cd0364141`;
- `s` MUST be in
  `[1, 0x7fffffffffffffffffffffffffffffff5d576e7357a4501ddfe92f46681b20a0]`;
  and
- recovery over `commonClaimDigest` MUST equal `claim.authority` and MUST NOT
  return the zero address.

EIP-2098 compact signatures and `v` values `0` or `1` are not accepted.

### Contract authority

When the returned code is nonempty:

1. require a nonempty signature of at most 8,192 bytes;
2. perform a `staticcall` at the evaluation block to
   `isValidSignature(commonClaimDigest, authoritySignature)`;
3. require the call to succeed; and
4. require exactly one canonical ABI-encoded `bytes4` equal to
   `0x1626ba7e`.

Raw four-byte return data, malformed ABI, incorrect padding, trailing return
data, reverts, and every other value are invalid. A contract authority MUST NOT
fall back to EOA recovery. Counterfactual or undeployed-contract signatures are
unsupported.

## Proof Key

Methods with a deterministic publication slot use:

```solidity
PROOF_KEY_TYPEHASH = keccak256(
  "ENSRecordVerificationProofKey(bytes32 domainSeparator,uint32 authorityVersion,address authority,bytes32 node,bytes32 recordTypeHash,bytes32 recordKeyHash,bytes32 methodHash)"
);

proofKey = keccak256(
  abi.encode(
    PROOF_KEY_TYPEHASH,
    domainSeparator,
    authorityVersion,
    authority,
    node,
    keccak256(UTF8(recordType)),
    keccak256(UTF8(recordKey)),
    keccak256(UTF8(method))
  )
);
```

All values are derived from the live record, descriptor, and authority
snapshot. `valueHash`, `target`, timestamps, signatures, and proof URI are
not proof-key inputs.

`https-origin.v1` and `dns-txt.v1` use the proof key. A method that retrieves
one envelope from descriptor `u` does not.

## Unfrozen v0 Parameters

Stable v0 conformance still requires:

- an exact ENSIP-15 normalization-data release;
- finite JSON nesting, member-count, and string limits;
- executable EIP-712 and proof-key intermediate vectors; and
- a decision on proof reactivation when the same authority later regains the
  same live state.
