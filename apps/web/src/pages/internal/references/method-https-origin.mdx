# Method: `https-origin.v1`

This method proves live publication by the WebPKI-authenticated HTTPS origin
derived from one ENS text record.

## Applicability

| Property          | Requirement                  |
| ----------------- | ---------------------------- |
| `recordType`      | `text`                       |
| Record value      | Nonempty strict UTF-8 string |
| Descriptor method | `https-origin.v1`            |
| Descriptor `u`    | Forbidden                    |
| Result type       | `control`                    |
| Maximum lifetime  | 31,536,000 seconds           |

The method applies to any text key. The exact key remains bound through the
common claim and proof key.

## URL Acceptance

Given the exact decoded text value:

1. Reject any ASCII whitespace or C0 control code point.
2. Parse the complete value as an absolute URL using the
   [WHATWG URL Standard](https://url.spec.whatwg.org/), without supplying a
   base URL.
3. Require scheme `https:`.
4. Require a nonempty host.
5. Require empty username and password.
6. Reject a domain host whose serialized hostname ends in `.`.
7. Reject an IPv6 zone identifier.

Path, query, and fragment are permitted but do not affect the method target.
They remain bound by `valueHash`.

The canonical `target` is the serialized WHATWG origin. The serialization
MUST:

- lowercase and A-label a domain host;
- omit port `443`;
- preserve a non-default port; and
- use canonical WHATWG IPv4 or bracketed IPv6 serialization.

An opaque origin or serialization equal to `null` is invalid.

## Proof Location

Calculate the common `proofKey`. Encode its 32 bytes as 64 lowercase
hexadecimal characters without `0x`.

The exact request URL is:

```text
<target>/.well-known/ens-record-verification/<proof-key-hex>
```

The target origin MUST be used exactly. No descriptor URI, caller override,
alternate path, search, or fallback location is permitted.

## Request Policy

The verifier MUST:

1. issue one credentialless `GET` request to the exact proof URL;
2. require WebPKI-authenticated TLS and service-identity validation for the
   derived host;
3. send no cookies, authorization, proxy authorization, client certificate,
   referrer, or other ambient credentials;
4. reject every redirect without following it;
5. require status `200`;
6. require media-type essence `application/json`;
7. disable MIME sniffing;
8. enforce a 256 KiB limit on the decoded response body while streaming; and
9. enforce finite connection, response-header, body, and total deadlines.

Parameters on `application/json`, including `charset=utf-8`, do not change
the required strict UTF-8 decoding.

An implementation MUST bound compressed input as well as decoded output. The
interoperable content-coding set and exact deadline values are not yet frozen;
an unknown or malformed content coding is invalid.

## Network Policy

A server verifier MUST prevent the request from reaching loopback, private,
link-local, multicast, documentation, benchmarking, reserved, or otherwise
non-globally-reachable IPv4 or IPv6 destinations.

It MUST apply this policy:

1. after name resolution and before connection;
2. to every connection attempt; and
3. to the actual connected peer address.

DNS rebinding, proxy configuration, or connection reuse MUST NOT bypass the
check. If the runtime cannot observe or constrain the connected peer, it cannot
perform conformant server verification for this method.

## Proof Schema

The response is the common closed proof envelope with:

```json
{ "proof": {} }
```

`proof` MUST contain no members. Target evidence is successful live
publication at the exact derived URL.

## Method Verification

In addition to every common check, require:

1. the live record and descriptor satisfy this method's applicability rules;
2. URL parsing produces the expected canonical target;
3. the proof key and proof URL are derived from live common inputs;
4. the HTTPS request satisfies every transport and network rule;
5. the response contains one valid closed envelope;
6. every common claim field matches, including
   `claim.method == "https-origin.v1"` and the derived target;
7. the authority signature is valid;
8. `proof` is exactly empty; and
9. common and method lifecycle checks pass.

Network, TLS, CORS, and timeout failures are unavailable, not proof that a
signature is invalid.

## Freshness

`methodEvidenceValidUntil` is absent. HTTP freshness can only shorten
`methodEvidenceCacheUntil`; it cannot extend the common five-minute cache
ceiling or any hard expiry.

A fresh evaluation SHOULD revalidate or bypass a reusable HTTP cache.
`Cache-Control: no-store` forbids storing the response but does not invalidate
the evaluation that consumed it.

## Browser Boundary

A browser implementation MUST obey the same URL, redirect, status, media type,
body, and envelope rules. CORS failure is non-positive.

Browsers generally cannot enforce connected-peer address policy or fully
control ambient transport behavior. A browser SDK MUST disclose those missing
checks and MUST NOT claim the server-runtime conformance profile.

## Unfrozen v0 Parameters

Stable `https-origin.v1` conformance still requires:

- executable WHATWG URL acceptance and serialization vectors;
- the accepted HTTP content-coding set;
- exact timeout and cache-request policy;
- globally reachable address test vectors;
- registration of the `ens-record-verification` well-known suffix; and
- a frozen browser conformance statement.
