# DNS TXT Methods

These methods verify that current exact-name authority authorized a record and
the record-derived DNS zone publishes the selected proof hash under DNSSEC.

## Concrete Profiles

| Identifier                  | Selector and target source                                 |
| --------------------------- | ---------------------------------------------------------- |
| `dns-txt.url.v1`            | `text("url")`; absolute HTTPS URL DNS host                 |
| `dns-txt.email-domain.v1`   | `text("email")`; mailbox domain                            |
| `dns-txt.https-endpoint.v1` | `text("agent-endpoint[...]")`; absolute HTTPS URL DNS host |

Common properties:

| Property               | Value                                     |
| ---------------------- | ----------------------------------------- |
| Relationship           | `control`                                 |
| Freshness              | `live-publication`                        |
| Descriptor             | `ensrv1 a=1 m=<profile> u=<uri> h=<hash>` |
| Maximum claim lifetime | 30 days                                   |
| Maximum DNS cache      | `min(validated TTL, 5 minutes)`           |

The generic identifier `dns-txt` is invalid.

## Target Derivation

URL and endpoint profiles use the `https-origin.v1` URL parser and require a DNS
host; IP literals are unsupported.

The email profile requires exactly one final `@`, a non-empty local part, no
display name or comments, and a valid IDNA domain. The method verifies domain
control, not mailbox control.

Convert the domain to lowercase ASCII, remove one trailing root dot, and require
valid DNS wire length. The claim target is:

```text
dns:<ascii-domain>
```

## TXT Owner And Value

Encode `proofKey` as lowercase RFC 4648 base32 without padding, producing 52
characters. Query:

```text
<base32-proof-key>._ens-record-verification.<ascii-domain> TXT
```

Concatenate character strings only within each TXT RDATA. Exactly one protocol
RDATA MUST exist:

```text
ensrv1 h=<lowercase-0x-proof-hash>
```

The TXT `h` MUST equal descriptor `h`. No protocol RDATA returns
`proof_unavailable`; conflicting or multiple protocol RDATA values return
`proof_invalid`.

## DNSSEC

The verifier MUST validate the entire answer and alias chain to an accepted
DNSSEC trust anchor. Unsigned, bogus, indeterminate, or unvalidated DNS returns
`none/insecure_dns` and cannot produce a control relationship.

Use the minimum TTL across the validated answer and CNAME/DNAME chain. Retry a
truncated UDP response over TCP. Apply authenticated negative-cache TTLs only
within the method's 5-minute cap.

## Proof Resource

Fetch descriptor `u`, enforce common fetch rules, and require decoded body hash
equal to descriptor `h`. The body is the strict common envelope with empty
`methodProof`.

## Verification

1. Resolve live record and descriptor at one ENS block.
2. Derive DNS target and `proofKey`.
3. Resolve and DNSSEC-validate the claim-specific TXT RRset.
4. Require exactly one matching proof hash.
5. Fetch and hash proof bytes.
6. Match the strict claim and verify current exact-name authority.
7. Apply claim and DNS freshness.
8. Return `verified/control` with `dnssec: "validated"`.

## Meaning

Allowed:

```text
DNSSEC-authenticated zone published a matching proof.
```

Forbidden:

```text
Mailbox control verified
Official domain
Safe domain
```
