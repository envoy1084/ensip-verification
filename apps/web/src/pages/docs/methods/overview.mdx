# Method Profiles

A method profile defines how a verifier derives an external target from a live
ENS record and how the target proves the common claim. A descriptor selects one
concrete method.

## Version 1 Registry

| Method                                               | Records                       | Verification type | Evidence                                      |
| ---------------------------------------------------- | ----------------------------- | ----------------- | --------------------------------------------- |
| [`https-origin.v1`](./https-origin)                  | HTTPS URL text records        | `control`         | Live proof served by the derived HTTPS origin |
| [`dns-txt.url.v1`](./dns-txt)                        | `text("url")`                 | `control`         | DNSSEC-authenticated proof hash               |
| [`account-signature.eip155.v1`](./account-signature) | Supported EVM address records | `control`         | EOA or ERC-1271 target signature              |
| [`account-signature.bip322.v1`](./account-signature) | Bitcoin `addr(0)`             | `control`         | BIP-322 target signature                      |

Every version 1 method requires evidence from the external target. Version 1
does not define an attestation method.

## Common Requirements

Before applying a method, a verifier:

1. resolves the target record and descriptor at one evaluation block;
2. derives the exact `valueHash` from the live resolver bytes;
3. determines current exact-name ENS authority at that block;
4. parses the proof envelope and compares every common claim field;
5. checks the proof validity interval;
6. applies the selected method to the same common claim.

A method succeeds only when its evidence proves the complete record-bound
claim. Proving a target without matching the live ENS record is insufficient.

## Requirements For New Methods

A new method specification MUST define:

- an immutable method identifier;
- supported resolver selectors;
- one canonical target derivation;
- permitted descriptor publication modes;
- exact proof-envelope fields;
- exact bytes or digest proven by the target or issuer;
- validity, freshness, and revocation rules;
- deterministic acceptance and rejection conditions;
- security boundaries and interoperability requirements.
