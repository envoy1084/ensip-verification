# Method Profiles

A verification method defines the check performed after current ENS authority
signs the record. For example, a method can check a website, DNS domain, or
blockchain account. Each verification record selects one method.

## Registry

| Identifier                                           | Selectors                    | Relationship    | `u`       | `h`       | Maximum lifetime |
| ---------------------------------------------------- | ---------------------------- | --------------- | --------- | --------- | ---------------- |
| [`authority-signature.v1`](./authority-signature)    | Any supported selector       | `authorization` | Required  | Permitted | 90 days          |
| [`https-origin.v1`](./https-origin)                  | HTTPS URL text records       | `control`       | Forbidden | Forbidden | 30 days          |
| [`dns-txt.url.v1`](./dns-txt)                        | `text("url")`                | `control`       | Required  | Required  | 30 days          |
| [`dns-txt.email-domain.v1`](./dns-txt)               | `text("email")`              | `control`       | Required  | Required  | 30 days          |
| [`dns-txt.https-endpoint.v1`](./dns-txt)             | HTTPS `agent-endpoint[...]`  | `control`       | Required  | Required  | 30 days          |
| [`account-signature.eip155.v1`](./account-signature) | Supported EVM `addr` records | `control`       | Required  | Permitted | 90 days          |

This is a closed registry for version 1. Generic identifiers such as
`dns-txt`, `service-account`, and `issuer-attestation` are not concrete methods.

## Common Processing

Every method receives a context that has already passed:

1. ENSIP-15 name normalization;
2. same-block target and descriptor resolution;
3. descriptor parsing and method selection;
4. strict proof-envelope parsing;
5. exact common-claim comparison;
6. current exact-name authority validation;
7. common claim lifetime validation.

The method then:

1. validates selector compatibility;
2. derives one canonical target;
3. validates its closed `methodProof` object or live publication;
4. returns its fixed relationship and method freshness bound.

Method identifiers are immutable. An incompatible target derivation, proof
format, or validation rule requires a new identifier.

## Registering Another Method

A new concrete method specification must define:

- identifier and supported selectors;
- descriptor field policy;
- exact target derivation;
- proof location and closed proof schema;
- binding to the complete common claim digest;
- signature, issuer, or publication validation;
- maximum lifetime and cache bounds;
- revocation behavior;
- error mapping;
- conformance vectors.
