# Method: `https-origin.v1`

:::warning[Not yet discussed]
This method is an initial proposal. It has not yet been reviewed or agreed, and
its identifier, proof format, and validation rules may change.
:::

## Purpose

`https-origin.v1` demonstrates control of the HTTPS origin derived from an ENS
text record. The origin serves a proof envelope bound to the exact live record
and current ENS authority.

## Descriptor

```text
ensrv1 a=1 m=https-origin.v1
```

`u` is forbidden. The record value determines the proof origin and the protocol
determines the path.

## Target Derivation

Parse the exact text-record value with the WHATWG URL algorithm. Require an
absolute HTTPS URL without credentials, fragment, opaque host, or IPv6 zone
identifier. Serialize the origin using WHATWG rules, omitting port 443.

For:

```text
https://example.com/profile
```

the claim target is:

```text
https://example.com
```

## Proof Location

```text
<origin>/.well-known/ens-record-verification/<proof-key-hex>
```

`proof-key-hex` is the 32-byte proof key encoded as exactly 64 lowercase
hexadecimal digits without a `0x` prefix.

The origin returns status 200, no redirect, and media type:

```text
application/ens-record-verification+json
```

The `Content-Type` media-type essence must match exactly; parameters are
forbidden. The verifier uses WebPKI-authenticated TLS, sends no cookies,
authorization headers, or other ambient credentials, and accepts at most 256
KiB after content decoding. Only `identity` and `gzip` content encodings are
accepted, and decoded size MUST NOT exceed 20 times encoded size.

Before connecting, resolve the host and reject loopback, link-local, private,
carrier-grade NAT, documentation, multicast, and unspecified addresses. Apply
the same check to every returned address and the address actually used for the
connection.

The envelope contains the common claim and a `proof` object containing exactly
the common `authoritySignature`.
`validUntil - issuedAt` MUST NOT exceed 30 days. A live positive evaluation
MUST NOT be cached for more than five minutes.

## Verification

The verifier MUST:

1. derive the HTTPS origin and proof key from live ENS inputs;
2. fetch the deterministic same-origin resource without ambient credentials;
3. reject redirects, invalid WebPKI TLS, disallowed network destinations, and
   responses outside the defined status, media-type, encoding, or size rules;
4. parse the closed envelope and compare the complete common claim;
5. validate `proof.authoritySignature` for the live ENS authority;
6. reject any other fields in `proof`;
7. require the proof to be within its validity interval.

When every check succeeds, return `verified: true` with
`verificationType: "control"`. Otherwise return `verified: false`.

## Security Boundary

The method demonstrates control of the serialized origin for the exact ENS
record. It does not establish that any page, operator, or service on the origin
is safe, official, or non-malicious.
