# Method: `account-signature.eip155.v1`

This method verifies that current exact-name authority authorized an EVM address
record and the target account signed a target-chain proof binding the complete
common claim digest.

## Profile

| Property               | Value                                                         |
| ---------------------- | ------------------------------------------------------------- |
| Relationship           | `control`                                                     |
| Records                | Unambiguous EVM `addr(node, coinType)` records                |
| Freshness              | `portable-signed`                                             |
| Descriptor             | `ensrv1 a=1 m=account-signature.eip155.v1 u=<uri> [h=<hash>]` |
| Maximum claim lifetime | 90 days                                                       |
| Target                 | Protocol-canonical CAIP-10 account ID                         |

## Supported Coin Types

| Coin type   | CAIP-2 chain                               |
| ----------- | ------------------------------------------ | ------------------ |
| `60`        | `eip155:1`                                 |
| `0x80000000 | chainId`, for `1 <= chainId <= 0x7fffffff` | `eip155:<chainId>` |

Require exactly 20 resolver bytes. Serialize the target as:

```text
eip155:<canonical-base10-chain-id>:0x<40-lowercase-hex>
```

Coin type `0x80000000`, legacy EVM SLIP-44 types other than `60`, and non-EVM
types are unsupported. CAIP-10 itself does not define address
canonicalization; the lowercase form above is this method's profile.

## Target Signature

Target account signs:

```solidity
ENSRecordAccountProof(bytes32 commonClaimDigest,string account)
```

Target-chain EIP-712 domain:

```text
name:              ENS Record Account Proof
version:           1
chainId:           CAIP-10 eip155 reference
verifyingContract: CAIP-10 target address
```

The proof object is:

```json
{
  "targetSignature": "0x..."
}
```

For an EOA, require the same 65-byte canonical low-`s` ECDSA form as the common
authority signature and recover the target address. For a contract, call
ERC-1271 on the target chain and require `0x1626ba7e`. No RPC, no code, revert,
wrong magic, and invalid signature have distinct debug causes and map to
`target_proof_invalid` or `proof_unavailable` as appropriate.

## Proof Envelope

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x...",
    "recordType": "addr",
    "recordKey": "60",
    "valueHash": "0x...",
    "authorityVersion": "1",
    "method": "account-signature.eip155.v1",
    "target": "eip155:1:0x1234567890abcdef1234567890abcdef12345678",
    "issuedAt": "1783728000",
    "validUntil": "1791504000"
  },
  "authoritySignature": "0x...",
  "methodProof": {
    "targetSignature": "0x..."
  }
}
```

## Verification

1. Resolve native address bytes and descriptor at one ENS block.
2. Derive raw `valueHash` and canonical CAIP-10 target.
3. Fetch descriptor `u`; check `h` when present.
4. Match strict envelope and common claim.
5. Verify current exact-name authority signature.
6. Compute target-chain digest from complete common claim digest and target.
7. Verify target EOA or ERC-1271 signature on the target chain.
8. Apply expiry and return `verified/control`.

## Meaning

Allowed:

```text
Target EVM account signed a matching proof for this ENS address record.
```

Forbidden:

```text
Safe address
Known recipient
Trusted wallet
Non-malicious account
```
