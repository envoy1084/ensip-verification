# Method: `account-signature.eip155.v1`

## Purpose

`account-signature.eip155.v1` verifies that the current ENS authority and the
target EVM account signed the same common claim. It produces
`verified/control`.

## Supported Records

| ENS coin type                                               | CAIP-2 chain       |
| ----------------------------------------------------------- | ------------------ |
| `60`                                                        | `eip155:1`         |
| `0x80000000 \| chainId`, where `1 <= chainId <= 0x7fffffff` | `eip155:<chainId>` |

The resolver value must contain exactly 20 bytes. Coin type `0x80000000`, other
legacy EVM SLIP-44 types, and non-EVM coin types are unsupported.

## Discovery Descriptor

The descriptor requires `u` and permits `h`:

```text
ensrv1 a=1 m=account-signature.eip155.v1 u=https://proofs.example/alice-address.json
```

## Publisher Flow

1. Resolve the live address bytes.
2. Map the coin type to one EIP-155 chain.
3. Derive the CAIP-10 target.
4. Construct the common claim with a lifetime no longer than 90 days.
5. Sign the common claim with current ENS authority.
6. Sign the account-proof claim with the target account.
7. Publish the envelope at descriptor `u`.
8. Add `h` when byte-level resource integrity is required.
9. Set the verification descriptor in ENS.

## Proof Location

The proof location is descriptor `u`. Version 1 permits HTTPS and applies the
common retrieval policy.

## Proof Payload

The target account signs this exact EIP-712 type:

```text
ENSRecordAccountProof(bytes32 commonClaimDigest,string account)
```

Domain:

```text
name:              ENS Record Account Proof
version:           1
chainId:           CAIP-10 eip155 chain reference
verifyingContract: CAIP-10 account address
```

Envelope method proof:

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "addr",
    "recordKey": "60",
    "valueHash": "0x<64-lowercase-hex>",
    "authorityVersion": "1",
    "method": "account-signature.eip155.v1",
    "target": "eip155:1:0x1234567890abcdef1234567890abcdef12345678",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x<65-byte-signature>",
  "methodProof": {
    "targetSignature": "0x<signature>"
  }
}
```

## Verifier Flow

1. Resolve the live address record and descriptor at one block.
2. Require a supported coin type and 20-byte address value.
3. Derive the CAIP-10 target and exact `valueHash`.
4. Fetch and parse the envelope.
5. Compare the common claim and validate current ENS authority signature.
6. Require `methodProof` to contain only `targetSignature`.
7. Construct the account-proof EIP-712 digest.
8. Validate the target signature on the target chain.
9. Apply common lifecycle checks.

## Validation Rules

For an EOA target, require a 65-byte secp256k1 signature with canonical low `s`
and `v` equal to 27 or 28. For a contract target, call ERC-1271 and require
`0x1626ba7e`.

| Check                                   | Failure                |
| --------------------------------------- | ---------------------- |
| Coin type or address length unsupported | `unsupported_record`   |
| CAIP-10 target differs                  | `target_mismatch`      |
| Target-chain RPC unavailable            | `proof_unavailable`    |
| EOA or ERC-1271 validation fails        | `target_proof_invalid` |

## Result

Successful validation returns `verified/control` for the canonical CAIP-10
account.

## Cache And Lifecycle

Maximum claim lifetime is 90 days. Target signatures are portable, but cached
results remain bounded by live ENS state, current ENS authority, claim expiry,
and client policy. A contract-account check uses a target-chain block selected
under client finality policy.

## Security Considerations

The method verifies control of the target account at evaluation time. It does
not establish that the account is uncompromised, safe to pay, or legally owned
by the ENS authority.

## UI Copy

Allowed:

- `Target account signed a matching proof.`
- `Address control verified for this ENS record.`

Forbidden:

- `Safe address.`
- `Verified owner.`
- `Official wallet.`

## Example

```text
addr(60) = 0x1234567890abcdef1234567890abcdef12345678
text("verification[addr][60]") = "ensrv1 a=1 m=account-signature.eip155.v1 u=https://proofs.example/alice-address.json"
target = eip155:1:0x1234567890abcdef1234567890abcdef12345678
```
