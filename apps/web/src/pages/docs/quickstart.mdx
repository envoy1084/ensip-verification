# Quickstart

This example demonstrates control of the HTTPS origin `https://example.com`
for the current `url` record on `alice.eth`. The origin publishes a proof bound
to the exact record, and the current ENS authority signs the same claim.

```text
alice.eth
└─ text("url") = "https://example.com/profile"
```

## Publish A Verification

### 1. Set The Verification Record

Add this text record to the same ENS name:

```text
text("verification[text][url]") = "ensrv1 a=1 m=https-origin.v1"
```

The value says:

- use authority rules version `1`;
- use the `https-origin.v1` method;
- derive the proof location from the URL record.

### 2. Create And Sign The Claim

Resolve the current `url` value and construct:

```json
{
  "name": "alice.eth",
  "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
  "recordType": "text",
  "recordKey": "url",
  "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
  "authorityVersion": "1",
  "method": "https-origin.v1",
  "target": "https://example.com",
  "issuedAt": "1783728000",
  "validUntil": "1786320000"
}
```

`valueHash` is the hash of the exact string
`https://example.com/profile`. `target` is the HTTPS origin derived from that
string.

Use timestamps for the real publication. Sign this EIP-712 claim with the
current authority for `alice.eth`.

### 3. Publish The Proof

Place the claim and signature in the common proof envelope:

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
    "authorityVersion": "1",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x<65-byte-signature>",
  "methodProof": {}
}
```

For the example claim, publish it at:

```text
https://example.com/.well-known/ens-record-verification/3e1afa3eb523cdefc3d8faa94c15e05fe1af4fb5096f71e127890e3763f5a380
```

Return HTTP status 200 and:

```text
Content-Type: application/ens-record-verification+json
```

## Verify A Record

A verifier performs these steps:

1. Resolve `text("url")` and `text("verification[text][url]")` on `alice.eth`.
2. Confirm that both values were read at the same Ethereum block.
3. Hash the exact URL record and derive `https://example.com`.
4. Calculate the proof path and fetch the JSON envelope.
5. Compare every signed field with the current ENS record.
6. Confirm that the signature belongs to the current authority for `alice.eth`.
7. Confirm that the proof is currently published by `https://example.com`.
8. Check expiry and cache limits.

Together, these checks establish that the current ENS authority authorized the
exact live record and demonstrated control of its HTTPS origin. If every check
passes, return:

```text
verified/control
```

Otherwise return `none` with an [error code](./reference/errors). The original
`url` record remains available through normal ENS resolution.

The exact hashes for this example are available in the
[test vector](./reference/test-vectors).
