# Quickstart

This example verifies `text("url")` with `https-origin.v1`.

## Publish

Set the target:

```text
text("url") = "https://example.com/profile"
```

Set the descriptor:

```text
text("verification[text][url]") = "ensrv1 a=1 m=https-origin.v1"
```

Resolve the final live value, compute its raw UTF-8 `valueHash`, and create the
strict claim:

```json
{
  "name": "alice.eth",
  "node": "0x...",
  "recordType": "text",
  "recordKey": "url",
  "valueHash": "0x...",
  "authorityVersion": "1",
  "method": "https-origin.v1",
  "target": "https://example.com",
  "issuedAt": "1783728000",
  "validUntil": "1786320000"
}
```

Sign it with current exact-name authority. Compute `proofKey`, then publish:

```text
https://example.com/.well-known/ens-record-verification/<proof-key>
```

with:

```json
{
  "v": "ensrv1",
  "claim": {},
  "authoritySignature": "0x...",
  "methodProof": {}
}
```

## Verify

```text
1. Normalize the ENS name with ENSIP-15.
2. Resolve target and descriptor through Universal Resolver at one block.
3. Parse descriptor and select Authority Algorithm 1 and https-origin.v1.
4. Hash exact live target bytes.
5. Derive canonical HTTPS origin and proofKey.
6. Fetch the deterministic same-origin proof under client privacy policy.
7. Parse the strict envelope and match all signed claim fields.
8. Resolve current exact-name authority and verify EOA or ERC-1271 signature.
9. Enforce issued interval, authority expiry, publication freshness, and cache bounds.
10. Return verified/control or none/<error>.
```

The result means the HTTPS origin currently publishes a proof authorized by
current exact-name authority. It does not mean the website is safe or official.
