# Build a Verifier

## Components

```ts
interface VerificationEngine {
  verify(
    input: VerifyInput,
    policy: VerificationPolicy,
  ): Promise<VerificationResult>;
}

interface EnsReader {
  resolvePair(
    input: RecordSelector,
    block: BlockRef,
  ): Promise<{
    value: Uint8Array;
    descriptor: string;
    resolver: Address;
    blockNumber: bigint;
    blockHash: Hex;
  }>;
  resolveAuthority(
    name: string,
    version: number,
    block: BlockRef,
  ): Promise<Authority>;
}

interface MethodVerifier {
  id: string;
  deriveTarget(context: MethodContext): string;
  verify(context: MethodContext): Promise<MethodResult>;
}
```

`EnsReader` uses Universal Resolver for records and the selected authority
algorithm for ownership. Method adapters cannot override authority.

## Pipeline

```text
normalize
  -> validate selector
  -> select evaluation block
  -> Universal Resolver target + descriptor
  -> parse closed descriptor
  -> select authority version and concrete method
  -> compute raw valueHash and canonical target
  -> retrieve proof under privacy/fetch policy
  -> parse strict JSON and method schema
  -> match complete common claim
  -> enforce signed interval
  -> resolve and verify current exact-name authority
  -> validate method evidence bound to common digest
  -> apply expiry, revocation, freshness, and cache bounds
  -> result
```

## Parser Boundaries

Process untrusted input in this order:

1. enforce byte limit;
2. validate UTF-8 and reject BOM;
3. reject duplicate JSON members before map parsing;
4. enforce JSON depth, member, and string limits;
5. validate common schema;
6. validate exact method schema;
7. convert canonical decimal integers with explicit range checks;
8. encode EIP-712 values.

JSON Schema alone cannot reject duplicate members or enforce every numeric
range.

## Network Boundary

Use one shared fetcher for URI methods. It enforces TLS, SSRF address blocking,
DNS-rebinding defense, redirect policy, timeouts, encoded and decoded size,
decompression ratio, content type, and no ambient credentials.

Browser CORS failure maps to `proof_unavailable`. Browser SDKs may use a
user-selected privacy proxy; the proxy is not a trust root because signatures
and optional `h` remain client-verified.

## Snapshot Boundary

Target, descriptor, Registry, Base Registrar, and Name Wrapper reads use one
block reference. Retain block number and hash. Re-evaluate if the block is
reorganized out.

Target-chain ERC-1271 validation uses an explicit block on the CAIP target
chain. Record that chain and block in debug output.

## Conformance

A conforming verifier passes all parser, hash, EIP-712, authority, method,
lifecycle, fetch-policy, and error-precedence vectors. High-trust integrations
must not depend only on an indexer-provided positive result.
