# Wallet and UI Integration

This page defines presentation guidance, not additional protocol states.

## Retrieval Defaults

Do not fetch third-party proof resources during passive profile rendering by
default. Direct retrieval reveals the ENS name, target record, IP address, and
time of interest to the proof host.

Recommended client modes:

| Mode              | Behavior                                                                |
| ----------------- | ----------------------------------------------------------------------- |
| `local-only`      | Perform no third-party request; return `privacy_blocked` when required. |
| `fetch-on-action` | Retrieve only after an explicit verification action.                    |
| `privacy-proxy`   | Route requests through a disclosed proxy.                               |
| `direct`          | Retrieve directly after policy or user approval.                        |

## Display Contract

| Relationship           | Permitted text                                                          |
| ---------------------- | ----------------------------------------------------------------------- |
| `authorization`        | “Current ENS authority authorized this exact record.”                   |
| `control` with HTTPS   | “Control of the HTTPS origin was demonstrated for this ENS record.”     |
| `control` with DNS     | “Control of the DNSSEC-authenticated domain was demonstrated.”          |
| `control` with account | “Control of the target account was demonstrated for this ENS record.”   |
| `attestation`          | “An issuer accepted under client policy attested to this record claim.” |

Do not display “safe,” “official,” “trusted,” “verified owner,” “not phishing,”
or “endorsed by ENS.”

Always make the target record visible independently of the verification result.
Do not hide an ordinary ENS record because its verification is absent, invalid,
unsupported, expired, or unavailable.

## Failure Display

Most `none` results require no badge. When a user explicitly requests
verification, distinguish:

- not configured;
- unsupported by this client;
- temporarily unavailable;
- configured but invalid;
- expired or revoked;
- blocked by privacy policy.

Use the canonical error and retry category rather than inferring from exception
text.

## Freshness

Display `checkedAt` and do not present cached evidence after `cacheUntil`.
Before a payment, signature, account binding, or agent connection, perform the
live checks required by the selected method even if a passive display cache is
still valid.
