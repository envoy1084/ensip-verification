## Conformance Coverage

The corpus is not complete. A conforming release also requires vectors for:

- ENSIP-15 valid and invalid names;
- every descriptor field and lexical boundary;
- exact text, address, contenthash, and data hashing;
- duplicate JSON members and parser resource limits;
- wrapped, unwrapped, `.eth`, subname, wildcard, and ERC-1271 authority cases;
- URL and DNS target derivation;
- DNSSEC answer, alias, conflict, and TTL behavior;
- ENSIP-9/11 to CAIP-10 mapping and target signatures;
- exact expiry, future issuance, revocation, and cache bounds;
- SSRF, redirect, timeout, size, and decompression rejection;
- every primary error.

Each vector must contain exact input bytes and one exact expected value or
error. Final interoperability requires two independent implementations passing
the same complete corpus.
