# Test Vectors

The public `test-vectors` directory is the machine-readable conformance corpus.
A complete implementation must cover:

## Core

- ENSIP-15 normalized names and namehash;
- verification-key construction, including nested brackets;
- valid, malformed, duplicate, unknown, and unsupported descriptors;
- raw `valueHash` for text, address, contenthash, and data bytes;
- EIP-712 type hash, domain separator, common digest, and `proofKey`;
- canonical decimal and hex parsing;
- duplicate JSON member rejection.

## Authority

- unwrapped `.eth` registrant versus Registry manager;
- exact unwrapped subname across parent transfer and re-registration;
- wrapped owner, child expiry, and parent grace behavior;
- EOA signatures;
- ERC-1271 valid, wrong magic, revert, and unavailable calls;
- wildcard/offchain record with no authenticated exact authority;
- unsupported authority version.

## Methods

- WHATWG/IDNA URL targets and invalid cases;
- deterministic HTTPS proof path;
- DNS base32 owner, DNSSEC states, TXT conflicts, and TTL cap;
- ENSIP-9/11 to CAIP-10 EVM mapping;
- target-chain EIP-712 digest, EOA, and ERC-1271 validation;
- authority-only empty method proof.

## Lifecycle And Network Policy

- future issuance, exact expiry, excessive signed interval;
- descriptor deletion/change and live value change;
- evaluation-block reorganization;
- SSRF addresses, DNS rebinding, redirects, timeouts, body/decompression limits;
- privacy-blocked and retryability results;
- cache-bound calculations.

Vectors contain exact input bytes and exact expected output or error. At least
two independent implementations should pass the corpus before finalization.
