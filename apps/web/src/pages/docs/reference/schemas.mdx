# Schemas

Machine-readable common schema:

- <a href="/schemas/ens-record-verification-proof.schema.json">
    Record Verification proof schema
  </a>

The schema validates the common envelope and claim shape. Method profiles
validate `methodProof` as a separate closed object.

## Validation Order

1. Enforce a 256 KiB decoded-body limit.
2. Decode UTF-8 and reject a byte-order mark.
3. Tokenize JSON and reject duplicate members at every depth.
4. Enforce maximum depth 16, 128 members per object, and 8 KiB strings unless a
   stricter field limit applies.
5. Validate the common JSON Schema.
6. Range-check canonical decimal `uint32` and `uint64` strings.
7. Validate ENSIP-15 normalization and recompute `node`.
8. Validate the selected method's closed `methodProof` schema.
9. Compare every claim field with live derived values.
10. Encode the claim as the exact EIP-712 type.

Ordinary `JSON.parse` is insufficient for step 3 because it discards earlier
duplicate members.

## Signed Representation

The exact common type string is:

```text
ENSRecordVerification(string name,bytes32 node,string recordType,string recordKey,bytes32 valueHash,uint32 authorityVersion,string method,string target,uint64 issuedAt,uint64 validUntil)
```

JSON bytes are not canonicalized or signed. Descriptor `h`, when present, binds
the exact retrieved body bytes.
