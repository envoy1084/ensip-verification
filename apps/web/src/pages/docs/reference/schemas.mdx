# Schemas

Common JSON Schema:

```text
/schemas/ens-record-verification-proof.schema.json
```

## Envelope

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x...",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x...",
    "authorityVersion": "1",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x...",
  "methodProof": {}
}
```

## EIP-712 Type

```solidity
ENSRecordVerification(
  string name,
  bytes32 node,
  string recordType,
  string recordKey,
  bytes32 valueHash,
  uint32 authorityVersion,
  string method,
  string target,
  uint64 issuedAt,
  uint64 validUntil
)
```

No extensions are permitted.

## Parser Requirements Beyond JSON Schema

Before schema validation:

- reject invalid UTF-8 and BOM;
- reject duplicate members at any depth;
- enforce 256 KiB total bytes;
- enforce depth 16, 128 members/object, and field string limits.

After schema validation:

- range-check decimal `uint32` and `uint64` strings;
- validate ENSIP-15 name normalization;
- validate method-specific closed `methodProof` schema;
- encode parsed fields into the exact EIP-712 type.

The JSON byte serialization is not signed or canonicalized.
