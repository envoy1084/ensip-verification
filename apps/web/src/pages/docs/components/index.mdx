# Protocol Overview

:::warning[Work in progress]
This page has not been finalized. Requirements, formats, and examples may
change while the protocol is under discussion.
:::

This walkthrough verifies:

```text
alice.eth → text("url") → https://example.com/profile
```

A positive result requires approval from both the current `alice.eth` authority
and the HTTPS origin `https://example.com`.

## 1. ENS Records

The resolver contains the target record:

```text
text("url") = "https://example.com/profile"
```

This value alone does not prove control of `example.com`.

The name opts this record into verification with a companion text record:

```text
text("verification[text][url]") = "ensrv1 a=1 m=https-origin.v1"
```

The descriptor selects the common protocol (`ensrv1`), authority algorithm
(`a=1`), and target-verification method (`m=https-origin.v1`). There is no `u`
field because this method derives the proof location from the live URL.

## 2. Authority

Authority is the canonical account required to approve verification for the
exact ENS name. The verifier computes it from ENS ownership state; the proof
cannot choose it.

Assume `alice.eth` is an active, unwrapped `.eth` second-level name. Authority
Algorithm 1 reads the Base Registrar registrant and registration expiry:

```text
tokenId = uint256(keccak256(bytes("alice")))
authority = BaseRegistrar.ownerOf(tokenId)
          = 0x1234567890abcdef1234567890abcdef12345678
authorityValidUntil = BaseRegistrar.nameExpires(tokenId)
```

Wrapped names use the exact Name Wrapper owner. Other unwrapped names use the
exact Registry owner. Reverse names are unsupported.

Resolver operators and delegated record writers are not additional
authorities.

## 3. Common Claim

The record value is `https://example.com/profile`; its method target is
`https://example.com`. `valueHash` binds the complete URL, while HTTPS proves
control of the origin.

| Claim field        | Value                                      |
| ------------------ | ------------------------------------------ |
| `name`             | Normalized `alice.eth`                     |
| `node`             | `namehash("alice.eth")`                    |
| `recordType`       | `text`                                     |
| `recordKey`        | `url`                                      |
| `valueHash`        | Keccak-256 of the exact UTF-8 record value |
| `authorityVersion` | Descriptor field `a`                       |
| `authority`        | Account computed from live ENS state       |
| `method`           | Descriptor field `m`                       |
| `target`           | Canonical target derived by the method     |
| `issuedAt`         | Claim creation time                        |
| `validUntil`       | First time at which the claim is invalid   |

## 4. Authority Signature

The authority approves the complete claim as EIP-712 typed data:

```text
domain.name    = "ENS Record Verification"
domain.version = "1"
domain.chainId = 1

commonClaimDigest = EIP712Hash(domain, claim)
authoritySignature = authority.signTypedData(domain, claim)
```

The signature covers the typed claim, not its JSON serialization. EOA
signatures are checked by recovery; contract signatures use ERC-1271 at the ENS
evaluation block.

## 5. Proof Publication

The method derives a proof key from the protocol domain, authority version and
address, ENS node, record type and key, and method. It identifies one
deterministic publication slot.

The origin serves the envelope at:

```text
https://example.com/.well-known/ens-record-verification/<64-lowercase-hex-proof-key>
```

The complete envelope is:

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
    "authorityVersion": "1",
    "authority": "0x1234567890abcdef1234567890abcdef12345678",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x<authority-signature>",
  "proof": {}
}
```

The placeholder is replaced by the actual signature bytes. `proof` is `{}`
because serving the envelope from the exact WebPKI-authenticated origin is the
target evidence.

## 6. Verification

The verifier:

1. Normalizes `alice.eth` using ENSIP-15.
2. Reads the URL, descriptor, and authority state at one Ethereum block.
3. Requires both records to be non-empty and parses the exact descriptor
   versions without fallback.
4. Computes the current authority and any known authority expiry.
5. Recomputes `node`, `valueHash`, and the canonical target from live data.
6. Derives the proof key and fetches the exact well-known URL.
7. Requires valid WebPKI TLS, status `200`, `application/json`, no redirects,
   no ambient credentials, and the method's size and network limits.
8. Parses the closed envelope and rejects missing, duplicate, or unknown
   members.
9. Compares every derived claim field with live ENS state.
10. Validates the claim lifetime and every applicable authority or method
    expiry.
11. Validates `authoritySignature` for the computed authority.
12. Requires `proof` to be exactly `{}`.

Every check is required.

## 7. Result

When all checks succeed:

```json
{
  "verified": true,
  "verificationType": "control"
}
```

This proves that both the ENS authority and HTTPS origin approved the exact live
record. It does not prove safety, identity, reputation, or legal ownership.

The maximum signed lifetime for `https-origin.v1` is one year. A positive result
must be re-evaluated within five minutes and expires sooner when the claim,
authority, or method evidence expires.

Otherwise the verifier returns `{ "verified": false }`. The URL still resolves
normally.
