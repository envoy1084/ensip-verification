# Verifying Contenthash Records

## Overview

Version 1 checks that current ENS authority signed the exact bytes returned by
`contenthash()`. It uses `authority-signature.v1`.

## When To Use This Method

Use this flow when a client needs explicit authority authorization in addition
to ordinary contenthash resolution.

## Records To Set

```text
contenthash() = <raw contenthash bytes>
text("verification[contenthash]") = "ensrv1 a=1 m=authority-signature.v1 u=https://proofs.example/alice-contenthash.json"
```

## Proof To Publish

Publish a common envelope with:

```text
recordType = contenthash
recordKey  = ""
target     = ""
valueHash  = keccak256(rawContenthashBytes)
```

`methodProof` is an empty object.

## Verification Flow

1. Resolve the raw contenthash bytes and descriptor at one block.
2. Calculate `valueHash` from the raw bytes.
3. Fetch and parse descriptor `u`.
4. Compare the common claim.
5. Resolve current ENS authority and validate its signature.
6. Require an empty target and `methodProof`.
7. Apply lifecycle checks and return `verified/authorization`.

## Failure Cases

| Condition                        | Result                             |
| -------------------------------- | ---------------------------------- |
| Contenthash absent               | `none/record_missing`              |
| Raw bytes changed                | `none/value_mismatch`              |
| Non-empty target or method proof | `none/proof_invalid`               |
| Authority signature invalid      | `none/authority_signature_invalid` |

## Example

An IPFS contenthash is hashed in its binary resolver representation. Do not hash
an `ipfs://` display string or gateway URL.

## Security Notes

Authorization does not establish control of an IPFS peer, gateway, storage
provider, content author, or the content itself.
