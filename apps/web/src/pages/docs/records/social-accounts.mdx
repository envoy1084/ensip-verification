# Verifying Social Account Records

## Overview

Provider account records such as `com.github` are ENS text records. Version 1
supports authority authorization of their exact values. It does not define
provider-control methods.

## When To Use This Method

Use `authority-signature.v1` when an application needs explicit authorization
from current ENS authority for the published account string.

## Records To Set

```text
text("com.github") = "alice"
text("verification[text][com.github]") = "ensrv1 a=1 m=authority-signature.v1 u=https://proofs.example/alice-github.json"
```

## Proof To Publish

Publish a common envelope at descriptor `u` with:

```text
recordType = text
recordKey  = com.github
target     = ""
valueHash  = keccak256(bytes("alice"))
```

## Verification Flow

1. Resolve the exact provider account string and descriptor.
2. Hash the exact UTF-8 value.
3. Fetch and parse the common envelope.
4. Compare the claim with live ENS inputs.
5. Resolve current ENS authority and validate its signature.
6. Require empty target and `methodProof`.
7. Return `verified/authorization`.

## Failure Cases

| Condition                   | Result                             |
| --------------------------- | ---------------------------------- |
| Account record absent       | `none/record_missing`              |
| Proof unavailable           | `none/proof_unavailable`           |
| Account string changed      | `none/value_mismatch`              |
| Authority signature invalid | `none/authority_signature_invalid` |

## Example

Changing `com.github` from `alice` to `alice-dev` changes `valueHash`. The old
proof no longer validates even if the proof resource remains available.

## Security Notes

Authority authorization does not establish that the provider account exists or
is controlled by current ENS authority. Clients must not display provider
control as verified.
