# Verifying Email Records

## Overview

Version 1 can verify authorization of the exact email record and control of its
DNS domain. It does not prove control of, or access to, the mailbox.

## When To Use This Method

Use `authority-signature.v1` to prove current ENS authority authorization. Use
`dns-txt.email-domain.v1` when the email domain can publish DNSSEC evidence.

## Records To Set

```text
text("email") = "alice@example.com"
text("verification[text][email]") = "ensrv1 a=1 m=dns-txt.email-domain.v1 u=https://proofs.example/alice-email.json h=0x<64-lowercase-hex>"
```

## Proof To Publish

Publish the common envelope at descriptor `u`. Set claim target to:

```text
dns:example.com
```

Publish the envelope hash at the method-defined TXT owner derived from
`proofKey`.

## Verification Flow

1. Resolve the live email value and descriptor.
2. Hash the exact email string.
3. Derive `example.com` from the final `@`.
4. DNSSEC-validate the method TXT record.
5. Fetch and hash the proof envelope.
6. Validate the common claim and current ENS authority signature.
7. Apply lifecycle and DNS freshness.
8. Return `verified/control` for `dns:example.com`.

## Failure Cases

| Condition                            | Result                          |
| ------------------------------------ | ------------------------------- |
| Email syntax cannot produce a domain | `none/target_mismatch`          |
| DNS response unavailable             | `none/proof_unavailable`        |
| DNSSEC does not validate             | `none/insecure_dns`             |
| TXT or proof hash mismatch           | `none/proof_integrity_mismatch` |

## Example

For `alice@example.com`, verification covers `example.com`. Changing the local
part to `billing@example.com` changes `valueHash` and requires a new common
claim, even though the method target remains `dns:example.com`.

## Security Notes

Domain control does not establish mailbox access, mail delivery, employee
status, or identity of the person using the local part.
