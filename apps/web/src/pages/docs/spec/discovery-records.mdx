# Resolution and Discovery

This page maps resolver calls to verification text records. The normative rules
are defined by the [ENSIP](./ensip#discovery-records).

## Resolution Input

A verifier starts with an ENS name, a resolver function, and the function's
exact key or numeric argument. Together, the function and argument form the
record selector.

The name is ENSIP-15 normalized before constructing resolver calldata.

## Selector Mapping

| Resolver call          | `recordType`  | `recordKey`                 | Verification text key            |
| ---------------------- | ------------- | --------------------------- | -------------------------------- |
| `text(node, key)`      | `text`        | Exact key                   | `verification[text][<key>]`      |
| `addr(node, coinType)` | `addr`        | Canonical decimal coin type | `verification[addr][<coinType>]` |
| `contenthash(node)`    | `contenthash` | Empty string                | `verification[contenthash]`      |
| `data(node, key)`      | `data`        | Exact key                   | `verification[data][<key>]`      |

Text and data keys use exact concatenation. A key such as
`agent-endpoint[mcp]` produces:

```text
verification[text][agent-endpoint[mcp]]
```

Do not parse nested brackets. Match the fixed prefix and final `]`.

## Resolver Return Bytes

| Record type   | Bytes hashed as `valueHash`    | Missing value     |
| ------------- | ------------------------------ | ----------------- |
| `text`        | UTF-8 bytes of returned string | Empty string      |
| `addr`        | Returned native address bytes  | Zero-length bytes |
| `contenthash` | Returned contenthash bytes     | Zero-length bytes |
| `data`        | Returned data bytes            | Zero-length bytes |

Display decoding and target canonicalization occur after hashing.

## Snapshot

Resolve the target record and verification record through Universal Resolver
for the same exact DNS-encoded name and block reference. Pin subsequent
authority reads to that block.

If the evaluation block is reorganized before the result is consumed, discard
the result and evaluate again.

CCIP Read may obtain data offchain, but the callback is executed against the
same pinned Ethereum state. A gateway response does not define ENS authority.
