# Results and Errors

## Result

```ts
type VerificationResult =
  | {
      status: "verified";
      relationship: "authorization" | "control" | "attestation";
      method: string;
      name: string;
      node: `0x${string}`;
      recordType: string;
      recordKey: string;
      target: string;
      validUntil: number;
      checkedAt: number;
      cacheUntil: number;
      assurance?: VerificationAssurance;
      issuer?: IssuerMetadata;
    }
  | {
      status: "none";
      error?: VerificationError;
      retryable?: boolean;
      checkedAt?: number;
    };
```

There are no intermediate public trust states. Errors explain why no positive
result was produced.

## Error Precedence

Use the first applicable error that can be determined without performing work
blocked by client policy:

| Order | Error                         | Retryable                                     |
| ----: | ----------------------------- | --------------------------------------------- |
|     1 | `invalid_request`             | No                                            |
|     2 | `unsupported_record`          | No, until client support changes              |
|     3 | `resolution_unavailable`      | Yes                                           |
|     4 | `record_missing`              | Yes                                           |
|     5 | `not_configured`              | Yes                                           |
|     6 | `invalid_descriptor`          | No                                            |
|     7 | `unsupported_version`         | No, until client support changes              |
|     8 | `unsupported_method`          | No, until client support changes              |
|     9 | `privacy_blocked`             | No, until policy changes                      |
|    10 | `proof_unavailable`           | Yes                                           |
|    11 | `proof_integrity_mismatch`    | No                                            |
|    12 | `proof_invalid`               | No                                            |
|    13 | `claim_mismatch`              | No                                            |
|    14 | `value_mismatch`              | No                                            |
|    15 | `target_mismatch`             | No                                            |
|    16 | `not_yet_valid`               | Yes                                           |
|    17 | `expired`                     | No, until proof changes                       |
|    18 | `unsupported_authority`       | No, until ENS state or client support changes |

Method-specific errors map into this set.

## Assurance

Assurance metadata records checked evidence; it never changes public status.

```ts
type VerificationAssurance = {
  dnssec?: "validated" | "unsigned";
  proofIntegrity?: "hash-pinned" | "content-addressed";
  publication?: "live" | "portable" | "issuer-revocable";
  authority?: "eoa" | "erc1271";
};
```

An absent field means not checked or not applicable. `dnssec: "validated"`
requires a complete validated chain to an accepted trust anchor.

## UI Constraint

Display the exact relationship, for example:

```text
Current ENS authority authorized this record.
HTTPS origin published a matching proof.
Target account signed a matching proof.
Example Issuer attested to this claim.
```

Never translate the result into safe, official, trusted, non-malicious, legal
owner, or ENS-endorsed.
