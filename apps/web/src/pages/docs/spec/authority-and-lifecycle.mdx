# Authority and Lifecycle

Authority identifies the current exact-name ENS authority bound into the common
claim. It is independent of the resolver or account allowed to write resolver
records. Version 1 does not require the authority to sign the claim.

## Authority Algorithm 1

Algorithm 1 applies to ENS on Ethereum mainnet.

| Contract       | Address                                      |
| -------------- | -------------------------------------------- |
| ENS Registry   | `0x00000000000C2E074eC69A0dFb2997BA6C7d2e1e` |
| Base Registrar | `0x57f1887a8BF19b14fC0dF6Fd9B2acc9Af147eA85` |
| Name Wrapper   | `0xD4416b13d2b3a9Bae7AcD5D6C2BbDBE25686401`  |

Use the evaluation block for every call and its block timestamp for expiry.

1. Read `ENSRegistry.owner(node)`.
2. If it equals the Name Wrapper address:
   1. read the exact node with `NameWrapper.getData`;
   2. require a nonzero wrapped owner and unexpired wrapper expiry;
   3. select the wrapped owner;
   4. for a wrapped `.eth` second-level name, also require an unexpired Base
      Registrar registration and use the earlier expiry.
3. Otherwise, for an unwrapped `.eth` second-level name:
   1. calculate `tokenId = uint256(keccak256(bytes(label)))`;
   2. read `BaseRegistrar.ownerOf(tokenId)` and `nameExpires(tokenId)`;
   3. require a nonzero registrant and unexpired registration;
   4. select the registrant.
4. For every other exact name, require and select the nonzero Registry owner.

Do not fall back to an ancestor, resolver writer, Universal Resolver, wildcard
resolver, or CCIP Read gateway. Verification cannot succeed when the exact
authority cannot be determined. The selected address must equal descriptor
field `ca` and common-claim field `authority`.

## Subnames

An unwrapped Registry child does not inherit parent expiry. Parent transfer,
expiry, or re-registration does not delete the child owner. The current parent
owner can replace the child, but until then the exact child owner remains the
authority.

A wrapped child uses its own wrapper expiry. Do not apply an ancestor registrar
expiry to that child. A wrapped `.eth` second-level name itself remains bounded
by Base Registrar expiry.

## Validity

Using local evaluation time `now`, require:

```text
issuedAt <= now + 300
issuedAt < validUntil
now < validUntil
validUntil - issuedAt <= methodMaxLifetime
```

`issuedAt` is not a trusted timestamp. It bounds the proof interval and rejects
future-dated claims beyond the allowed clock skew.

The semantic expiry is the earliest applicable bound:

```text
effectiveValidUntil = min(
  claim.validUntil,
  authorityValidUntil?,
  methodEvidenceValidUntil?,
  issuerValidUntil?
)
```

Omit a bound only when the selected authority or method does not define it.

## Invalidation

Re-evaluation returns `verified: false` after any of these changes:

- target record changed;
- verification descriptor changed or was deleted;
- exact authority changed or expired;
- live method publication was removed;
- method evidence is revoked under the selected method;
- effective validity expired;
- evaluation block was reorganized.

Descriptor deletion is the common ENS-side revocation action. It takes effect
when a verifier performs a fresh ENS read.

## Caching

`effectiveValidUntil` is the semantic bound. `cacheUntil` is the earlier time at
which a client must re-evaluate:

```text
cacheUntil = min(
  effectiveValidUntil,
  ENS freshness bound,
  method freshness bound,
  HTTP or DNS freshness bound?,
  revocation next-update bound?,
  client policy bound
)
```

Live-publication methods cap positive caching at five minutes. HTTP freshness
and DNS TTLs may shorten that period but cannot extend it.
