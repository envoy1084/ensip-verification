# Claims and Signatures

Every concrete method uses the same common claim. Method-specific evidence
commits to its EIP-712 digest.

## Common Claim

The exact EIP-712 type string is:

```text
ENSRecordVerification(string name,bytes32 node,string recordType,string recordKey,bytes32 valueHash,uint32 authorityVersion,string method,string target,uint64 issuedAt,uint64 validUntil)
```

The type is closed. Do not add, remove, rename, or reorder fields.

| Field              | Source                                             |
| ------------------ | -------------------------------------------------- |
| `name`             | ENSIP-15 normalized input name.                    |
| `node`             | `namehash(name)`.                                  |
| `recordType`       | Selected resolver record type.                     |
| `recordKey`        | Exact selector key or canonical numeric parameter. |
| `valueHash`        | Keccak-256 of exact live resolver return bytes.    |
| `authorityVersion` | Descriptor field `a`.                              |
| `method`           | Descriptor field `m`.                              |
| `target`           | Canonical value derived by the method.             |
| `issuedAt`         | Signer-asserted Unix time in seconds.              |
| `validUntil`       | First invalid Unix time in seconds.                |

`issuedAt` and `validUntil` are JSON decimal strings and EIP-712 unsigned
integers. Reject signs, whitespace, leading zeroes, and values outside `uint64`.

## Domain

Authority Algorithm 1 on Ethereum mainnet uses:

```text
name:              ENS Record Verification
version:           1
chainId:           1
verifyingContract: 0xeEeEEEeE14D718C2B47D9923Deab1335E144EeEe
```

The Universal Resolver address is a domain-separation anchor. It does not
validate the signature.

## Authority Signature

For an EOA, accept only a 65-byte secp256k1 signature with canonical low `s` and
`v` equal to 27 or 28. EIP-2098 compact signatures are not accepted by version

1.

For a contract, call ERC-1271 `isValidSignature(digest, signature)` at the
evaluation block. Accept only `0x1626ba7e`. Treat a revert, malformed return, or
other value as `authority_signature_invalid`.

## Proof Key

```solidity
PROOF_KEY_TYPEHASH = keccak256(
  "ENSRecordVerificationProofKey(bytes32 domainSeparator,uint32 authorityVersion,bytes32 node,bytes32 recordTypeHash,bytes32 recordKeyHash,bytes32 methodHash)"
);

proofKey = keccak256(
  abi.encode(
    PROOF_KEY_TYPEHASH,
    domainSeparator,
    authorityVersion,
    node,
    keccak256(bytes(recordType)),
    keccak256(bytes(recordKey)),
    keccak256(bytes(method))
  )
);
```

Encode all strings as exact UTF-8 bytes. `node` already commits to the normalized
name. The key excludes record value and timestamps so one publication location
can be reused for renewal and record rotation.

## Proof Envelope

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
    "authorityVersion": "1",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "authoritySignature": "0x...",
  "methodProof": {}
}
```

The envelope and claim are closed objects. Detect duplicate members before
constructing a map. `methodProof` is a method-defined closed object.

The JSON bytes are not signed. Parse the claim, validate every field against
live inputs, and encode the resulting values as EIP-712.
