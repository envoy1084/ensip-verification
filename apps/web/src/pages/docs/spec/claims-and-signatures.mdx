# Claims and Target Proofs

Every method binds its evidence to the same common claim. The claim identifies
one ENS name, one resolver record, its exact live value, the current ENS
authority, and the external target derived by the method.

The protocol does not require a signature from the ENS authority. Publishing
the verification descriptor supplies the ENS-side association. Descriptor
field `ca` and claim field `authority` must both match live authority state, so
an authority change makes the existing descriptor non-positive.

## Common Claim

The exact EIP-712 type string is:

```text
ENSRecordVerification(string name,bytes32 node,string recordType,string recordKey,bytes32 valueHash,uint32 authorityVersion,address authority,string method,string target,uint64 issuedAt,uint64 validUntil)
```

The type is closed. Implementations MUST NOT add, remove, rename, or reorder
fields.

| Field              | Source                                               |
| ------------------ | ---------------------------------------------------- |
| `name`             | ENSIP-15 normalized input name.                      |
| `node`             | `namehash(name)`.                                    |
| `recordType`       | Selected resolver record type.                       |
| `recordKey`        | Exact selector key or canonical numeric parameter.   |
| `valueHash`        | Keccak-256 of the exact live resolver return bytes.  |
| `authorityVersion` | Descriptor field `a`.                                |
| `authority`        | Descriptor `ca`, matching live exact-name authority. |
| `method`           | Descriptor field `m`.                                |
| `target`           | Canonical external target derived by the method.     |
| `issuedAt`         | Proof publisher's Unix time in seconds.              |
| `validUntil`       | First Unix time at which the proof is invalid.       |

`issuedAt` and `validUntil` are JSON decimal strings and EIP-712 unsigned
integers. Reject signs, whitespace, leading zeroes, and values outside `uint64`.

## Domain

Version 1 on Ethereum mainnet uses:

```text
name:              ENS Record Verification
version:           1
chainId:           1
verifyingContract: 0xeEeEEEeE14D718C2B47D9923Deab1335E144EeEe
```

The Universal Resolver address is a domain-separation anchor. It does not
authorize the proof or participate in target-signature validation.

## Method Evidence

A method proves the common claim in one of three ways:

- live publication by the derived target, as in `https-origin.v1`;
- a target-native signature over the common claim digest, as in the account
  signature methods;
- an issuer attestation defined by a future method profile.

For a signature method, the target signs a method-specific message that commits
to the complete EIP-712 common claim digest. The method profile defines the
native signature scheme and exact message bytes.

## Proof Key

```solidity
PROOF_KEY_TYPEHASH = keccak256(
  "ENSRecordVerificationProofKey(bytes32 domainSeparator,uint32 authorityVersion,address authority,bytes32 node,bytes32 recordTypeHash,bytes32 recordKeyHash,bytes32 methodHash)"
);

proofKey = keccak256(
  abi.encode(
    PROOF_KEY_TYPEHASH,
    domainSeparator,
    authorityVersion,
    authority,
    node,
    keccak256(bytes(recordType)),
    keccak256(bytes(recordKey)),
    keccak256(bytes(method))
  )
);
```

The proof key excludes the record value and timestamps so the same publication
location can be reused after a record update or proof renewal. It includes the
authority so an authority transfer selects a different publication slot.

## Proof Envelope

```json
{
  "v": "ensrv1",
  "claim": {
    "name": "alice.eth",
    "node": "0x787192fc5378cc32aa956ddfdedbf26b24e8d78e40109add0eea2c1a012c3dec",
    "recordType": "text",
    "recordKey": "url",
    "valueHash": "0x34174bbdf078fba55709ff82e2d5929de2e915c964d18dc57907afc851781142",
    "authorityVersion": "1",
    "authority": "0x1234567890abcdef1234567890abcdef12345678",
    "method": "https-origin.v1",
    "target": "https://example.com",
    "issuedAt": "1783728000",
    "validUntil": "1786320000"
  },
  "methodProof": {}
}
```

The envelope and claim are closed objects. Implementations MUST detect duplicate
members before constructing a map. `methodProof` is a method-defined closed
object.

The JSON bytes are not signed. Parse the claim, compare every field with live
inputs, encode the fields as EIP-712, and then apply the selected method.
